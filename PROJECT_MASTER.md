## 2. EXPRESS API ROUTES

All routes live in `server/`. Every route except `/health` and `/auth/callback` requires a valid Shopify session token verified by `middleware/auth.js`.

| # | Method | Path | Purpose |
|---|--------|------|---------|
| 1 | GET | `/health` | Health check — Railway uses this to confirm the server is up |
| 2 | GET | `/auth/callback` | Shopify OAuth callback — exchanges code for access token |
| 3 | POST | `/webhooks/customers/redact` | GDPR — delete customer personal data on request |
| 4 | POST | `/webhooks/shop/redact` | GDPR — delete all shop data when merchant uninstalls |
| 5 | POST | `/webhooks/customers/data_request` | GDPR — respond to customer data export request |
| 6 | GET | `/api/diamonds` | Fetch all diamonds from Payal's API (supports filter params) |
| 7 | GET | `/api/diamonds/:id` | Fetch single diamond details by ID |
| 8 | POST | `/api/orders` | Submit a customer diamond order to Payal's API + save to DB |
| 9 | POST | `/webhooks/billing` | Handle Shopify billing events (subscription activated/cancelled) |

## 3. DATABASE TABLES

Database: **PostgreSQL on Supabase**, managed via **Prisma ORM**.
Schema file: `prisma/schema.prisma`

### sessions
> Managed by `@shopify/shopify-app-session-storage-prisma`. Do not remove any fields.

| Field | Type | Notes |
|-------|------|-------|
| id | String | Primary key |
| shop | String | Unique — merchant's myshopify.com domain |
| state | String | OAuth state param |
| isOnline | Boolean | Default: false |
| scope | String? | Approved OAuth scopes |
| expires | DateTime? | Session expiry |
| accessToken | String | Shopify access token |
| userId | BigInt? | Shopify user ID |
| firstName | String? | |
| lastName | String? | |
| email | String? | |
| accountOwner | Boolean | Default: false |
| locale | String? | |
| collaborator | Boolean? | Default: false |
| emailVerified | Boolean? | Default: false |
| refreshToken | String? | |
| refreshTokenExpires | DateTime? | |

### merchants
> One record per installed merchant shop.

| Field | Type | Notes |
|-------|------|-------|
| id | String | Primary key (cuid) |
| shopId | String | Unique — FK → sessions.shop |
| plan | String | Default: "free" |
| isActive | Boolean | Default: true |
| widgetEnabled | Boolean | Default: false — merchant must enable widget |

### orders
> Every diamond order placed through the widget.

| Field | Type | Notes |
|-------|------|-------|
| id | String | Primary key (cuid) |
| shop | String | FK → merchants.shopId |
| customerEmail | String | Buyer's email |
| diamondId | String | Payal's diamond ID |
| diamondDetails | Json | Full snapshot of diamond at time of order |
| status | String | Default: "pending" — pending / confirmed / shipped / cancelled |
| shopifyOrderId | String? | Set after Shopify order is created |
| payalOrderId | String? | Set after Payal confirms the order |
| createdAt | DateTime | Default: now() |

### subscriptions
> Shopify billing subscription records.

| Field | Type | Notes |
|-------|------|-------|
| id | String | Primary key (cuid) |
| shop | String | FK → merchants.shopId |
| shopifyChargeId | String | Unique — Shopify's recurring charge ID |
| planName | String | e.g. "basic", "pro" |
| status | String | active / cancelled / frozen / expired |
| trialEndsAt | DateTime? | Null if no trial |
| billingOn | DateTime? | Next billing date |
| createdAt | DateTime | Default: now() |

## 4. ENVIRONMENT VARIABLES

File: `.env` (never commit) — template: `.env.example`

| Variable | Description | Example |
|----------|-------------|---------|
| `SHOPIFY_API_KEY` | Shopify app client ID from Partner Dashboard | `abc123...` |
| `SHOPIFY_API_SECRET` | Shopify app client secret | `shpss_...` |
| `SHOPIFY_SCOPES` | OAuth permission scopes requested | `read_products,write_orders` |
| `DATABASE_URL` | Supabase connection string (pooled — for Prisma runtime) | `postgresql://...?pgbouncer=true` |
| `DIRECT_URL` | Supabase direct connection string (for Prisma migrations) | `postgresql://...` |
| `PAYAL_API_URL` | Base URL of Payal's existing API | TBD — get from bhaiya |
| `PAYAL_API_KEY` | API key / token for Payal's API | TBD — get from bhaiya |
| `SESSION_SECRET` | Random secret for signing session cookies | Any long random string |
| `PORT` | Port Express API listens on | `4000` |
| `NODE_ENV` | Runtime environment | `development` / `production` |

> **Note:** `DATABASE_URL` uses Supabase's pgBouncer pooled URL for app queries.
> `DIRECT_URL` uses the direct (non-pooled) URL for `prisma migrate` — required by Prisma.

## 7. RAILWAY DEPLOYMENT CHECKLIST

### Before first deploy
- [ ] Railway account created and CLI installed (`npm i -g @railway/cli`)
- [ ] Log in: `railway login`
- [ ] Create new Railway project: `railway init`
- [ ] Add environment variables in Railway dashboard (all vars from Section 4)
- [ ] Confirm `Procfile` exists at project root with correct start commands
- [ ] Confirm `NODE_ENV=production` is set in Railway env vars

### Procfile (example)
```
web: node server/index.js
remix: npx remix-serve build/server/index.js
```
> Update this once the app is scaffolded and start commands are confirmed.

### Deploy steps
1. Push to GitHub — Railway auto-deploys on push (if GitHub integration enabled)
2. Or manual deploy: `railway up`
3. Check deploy logs in Railway dashboard
4. Hit `GET /health` on the deployed URL to confirm Express is up
5. Verify Remix app is accessible via the Railway-provided domain

### Post-deploy checks
- [ ] `/health` returns `200 OK`
- [ ] OAuth install flow completes on a dev store using the Railway URL
- [ ] GDPR webhooks registered and verified in Shopify Partner Dashboard
- [ ] Supabase connection live (check Railway logs for Prisma connection success)
- [ ] Theme Extension deployed via `shopify app deploy`

### Custom domain (optional)
- [ ] Add custom domain in Railway dashboard
- [ ] Update `shopify.app.toml` URLs to match the custom domain
- [ ] Re-run `shopify app deploy` to sync URL changes
